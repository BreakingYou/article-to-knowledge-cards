# 知识卡片生成器

## Overview

把一篇文章（粘贴的文本或本地 `.md`/`.txt` 文件）转化成最多 8 张可复习的知识卡片。目标不是摘要，而是**可记忆的知识单元**：一张卡片只承载一个知识点，讲清楚它是什么、为什么成立、怎么用。

核心纪律：**只写原文有的信息**。5~8 张是"信息足够时的常见区间"，不是配额。信息不足时宁可少出卡片、并在末尾说明缺口，也不编造、不硬凑数量。

## 输入判断

先判断用户给的是哪种输入，再决定处理路径：

| 情况 | 处理方式 |
| --- | --- |
| 直接粘贴的文本 | 直接进入「第 1 步：通读并定位主题」 |
| 提到本地 `.md` / `.txt` 文件 | 先用读取工具读出全文再处理 |
| 网页链接、PDF、图片、`.docx` | **不支持**：说明当前只支持粘贴文本和本地 Markdown/TXT，请用户提供文本或另存为 `.md`/`.txt` |
| 要求导出 Anki / apkg / 图形界面 | **不支持**：说明可输出 Markdown 卡片，用户可自行导入其他工具 |

若用户要求"卡越多越好"，以原文信息量为准，按下面的数量规则处理，并说明理由。

## 工作流程

### 第 1 步：通读并定位主题

一口气读完全文，写下一句话概括：**这篇文章真正想让人记住的是什么**。这一步决定取舍标准——与这句话无关的内容，即使段落很长也不进卡片。

### 第 2 步：拆出候选知识点

逐个章节/段落提取候选知识点，每条写成一个**可以独立成卡**的陈述句（形如"X 会导致 Y""用 Z 而不是 W 的原因"）。此阶段只列，不写解释。

判断"真正重要"的四个筛选信号：

1. **承载全文主线**：删掉它，文章的核心论点就垮了。
2. **可迁移**：能被用到别的场景，而不是只在这篇文章里成立的一次性细节。
3. **有解释力或可操作性**：解释了某个现象的原因，或给出能照做的方法/步骤。
4. **常被误解 / 易混淆**：纠正了直觉、反例、常见错误——这类知识点最容易丢分，价值最高。

明确**丢弃**的内容：背景铺垫、作者个人经历与情绪、重复表述、广告与致谢、纯装饰性举例、只出现一次的次要数据（除非它就是核心结论）。

### 第 3 步：合并去重，按"一卡一点"切分

- 语义相同的候选合并为一张卡片，**保留最完整、最准确的表述**，其余删除，不要在一张卡里堆几个版本。
- 一个候选里含两个知识点时，拆成两张；宁可两张各讲透，也不要一张含糊。
- 概念与它的应用方法可以同卡（属同一知识点），但"概念 A"与"概念 B"必须分开。

### 第 4 步：定数量

卡片**上限 8 张**，下限不设配额。按去重后的有效知识点数定卡片数，宁少勿凑：

| 有效知识点数 | 输出卡片数 |
| --- | --- |
| 6~8 | 与知识点数相等 |
| 9 及以上 | 按重要性排序取前 8，其余在末尾一行带过 |
| 5 | 5 张 |
| 2~4 | 有多少出多少，末尾说明"原文信息有限" |
| 1 或 0 | 出 1 张（0 则不出卡），说明原文更适合摘要而非卡片 |

遇到边界情况按下述规则裁决，不要自行放松：

- **恰好 6 个** → 出 6 张，不要为了接近 8 而拆分或补充。
- **知识点数的计数口径**：只数"能独立成卡且各有独立核心知识"的条目；同一事实的成因、条件、例子不单独计数，它们属于该卡的解释字段。拿不准时按小口径计数。
- **知识密度低（叙事、随笔、口号、清单）**：只要其内容是"可迁移的判断或方法"且原文有支撑，就计入；纯粹的个人经历、情绪、无论证的观点不计入。

**绝不为了凑到 5 张而拆分、重复或扩写原文没有的内容**；卡片数少于 5 张是正常结果，不需要为此道歉或额外解释。

### 第 5 步：填写四要素

每张卡片固定四部分：

| 字段 | 要求 |
| --- | --- |
| **标题** | 一句话点出这个知识点，最好自带信息量（"复利来自收益再投资，而非本金变多"优于"复利"）。14 字以内为宜。 |
| **核心知识** | 1~3 句陈述句，说出这条知识本身，必须能脱离原文独立读懂。 |
| **简明解释** | 说明原因、机制或适用条件——回答"为什么是这样"或"什么时候成立"。2~4 句，用大白话，不堆砌原文行话。 |
| **例子 / 自测** | 二选一或都写，至少保留其一。**例子**：原文有具体例子就精简沿用，不另行虚构；**自测问题**：能从原文找到明确答案的提问，问"为什么/怎么用/区别是什么"，避免只问"是什么"。 |

写作约束：

- 解释与例子可以做通俗化转述，但**事实、数字、结论、因果关系必须来自原文**。
- 原文没说明机制时，**在"简明解释"字段内写"原文未展开"**并说明缺什么，此时该字段可以短至一两句——这是对 2~4 句要求的唯一豁免。
- 确有必要补充外部常识才能让读者读懂时，在句末标注"（补充背景，非原文）"，且不超过一句；**只用于补充衔接，不得用于补出原文没有的结论、数据或因果**。
- 原文中的具体数字、专有名词、条件限定词（"仅在……时""除……之外"）要保留，这些往往就是考点。
- **自测问题的边界**：答案可以直接落位到原文某一处，或由原文两处以上内容直接并合得出；若需要引入原文没有的前提、外部常识或自由推论，就改用更贴近原文的问法（如把"为什么 X 能提高效率"降为"原文把 X 的作用归因于什么"）。
- 原文本身没有"为什么"可问时，自测问"是什么/有哪些/属于哪一类"即可，不要为了符合"为什么"模板而硬造因果。
- 只使用原文的视角，不评价文章好坏，不写"本文作者认为……"式的旁白。

**叙事类文本的额外口径**（随笔、个人经历、感悟）：只把其中能脱离作者个人场景复用的判断或方法做成卡片，个人经历与情绪只作为例子的素材；文章若通篇无可用知识点，按第 4 步"1 或 0"处理并如实说明。

### 第 6 步：自检

逐条核验，不合格就改或删卡，不要留着充数：

- [ ] 每张卡片只讲一个知识点，标题能概括全部内容
- [ ] 删除任意一张卡片，不会让另一张变得不完整（无交叉重复）
- [ ] 卡片中每条事实都能在原文找到出处，没有原文之外的结论
- [ ] 卡片总数不超过 8，且与实际知识点数量匹配，没有为凑数而拆分的卡片
- [ ] 自测问题都能用原文直接回答（可跨卡片，但不能依赖外部知识）
- [ ] 每张卡的解释与自测都没有出现"原文未展开"却仍写满机制的情况
- [ ] 顺序符合逻辑（按原文顺序，或"概念 → 方法 → 应用"）

## 输出格式

默认输出 Markdown：开头一句 30 字以内的主题概括，然后依次编号排列卡片。

```markdown
> 主题：<一句话概括这篇文章真正要让人记住什么>

## 卡片 1｜<标题>

- **核心知识**：<1~3 句>
- **简明解释**：<2~4 句，说明原因/机制/适用条件>
- **例子**：<原文中的例子，可精简>
- **自测**：<能从原文找到答案的问题>

## 卡片 2｜<标题>
...
```

`例子`、`自测` 至少保留其一，没有内容的字段整行省略，不留空占位；字段名保持这种加粗引导词形式，便于后续导入其他工具。

主题概括控制在 30 字以内，超长时压缩为"主语 + 核心结论"，宁可丢掉修饰词也不写成一个句子。

卡片之后按需追加一段说明（无内容则省略）：

```markdown
---
说明：原文有效知识点约 N 个，故只出 N 张卡；未成卡的次要要点：……（可选）
```

**输出位置**：用户指定了路径就按用户的；没指定且要求落盘时，写到 `<项目根>/knowledge-cards/<源文件名>-cards.md`（粘贴文本则用主题短名）。用户只要结果时直接在对话中输出。

## 常见陷阱

- **伪去重**：两张卡换个说法讲同一件事（"复利需要时间"与"长期投资更重要"），检查核心知识是否在讲同一个因果。
- **假例子**：为了让卡片好看而编一个原文没有的场景——不许。没有例子就不写，用自测问题补。
- **解释变常识**：解释段落写成泛泛的道理，读不到原文的机制。每句都要能指回原文。
- **一张卡塞满**：核心知识写成一大段并列要点。发现并列的核心结论超过两个，就该拆卡。
- **标题空壳**：标题只写名词（"复利""沉没成本"），读者看标题学不到东西。
- **数量当 KPI**：为了凑近 8 张而拆分、加"总结卡"、或把例子改写成独立卡片。卡片价值由覆盖主线的质量决定，不由张数决定。

## 示例

输入（节选）：

> ……人们常以为沉没成本应该计入决策，但理性决策只看边际收益与边际成本。一位创业者已投入 200 万做产品，市场反馈很差，此时"已经花的钱"不该影响是否继续的决策……

输出：

```markdown
> 主题：理性决策只比较未来的边际收益与成本，已投入的成本不应影响判断

## 卡片 1｜沉没成本不该进入决策

- **核心知识**：已经发生、无法收回的成本（沉没成本）不应影响当前决策，决策只应比较边际收益与边际成本。
- **简明解释**：沉没成本无论怎么决策都收不回来，把它计入会让人为了"对得起过去的投入"而继续错误的方向，属于非理性。
- **例子**：创业者已投入 200 万做产品，市场反馈很差；这笔已花的钱不应成为"继续做下去"的理由。
- **自测**：判断一个项目是否继续时，哪些成本应该被忽略？
```

## 不做什么

- 不抓取网页，不解析 PDF、图片、Office 文档
- 不生成 Anki 牌组（apkg）或其他专用格式
- 不提供图形界面或交互网页
- 不写与卡片无关的读后感、书评、延展科普
